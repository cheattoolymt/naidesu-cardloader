# 📇 naidesu-cardloader

> (何もかも)ないです — バイナリ ⇄ 紙のパンチカード変換ツール（A4 / 300dpi）

任意のファイル（バイナリ）を、A4に印刷できる「パンチカード」画像に変換し、
それを **印刷 → スキャン（または撮影）** して、再びバイナリに復元するための
完全ブラウザ完結（サーバ不要）の静的Webアプリです。

- **作成 (Creator)**: `バイナリ → カード画像(PDF / PNG / JPG) → 印刷`
- **読み取り (Decoder)**: `印刷物を300dpiでスキャン → 自動検出 → バイナリ復元`

pdf.js / jsPDF を利用し、外部サーバへデータを送りません（オフラインでも動作）。

---

## 🚀 使い方

`index.html` をブラウザで開くだけです（GitHub Pages 等の静的ホスティングでも動作）。

### ① 作成（バイナリ → 紙）
1. `creator.html` を開く
2. 変換したいファイルを選択（テキスト / 画像 / zip など何でも可）
3. 出力形式を選ぶ
   - **PDF**（複数ページを1ファイルに・推奨）
   - **PNG / JPG**（ページごとに個別ダウンロード）
4. 「カードを生成してダウンロード」
5. **A4に等倍（100% / 実サイズ）で印刷**（四隅の黒い■を切らないこと）

> 1ページの容量は **1140 byte**。1KB(1024byte)を余裕をもって1枚に収められます。
> これを超えるファイルは自動的に複数ページに分割されます（今は1KB/枚。将来2KBも視野）。

### ② 読み取り（紙 → バイナリ）
1. 印刷したカードを **300dpi程度でスキャン**、または正面から真っ直ぐ撮影
2. `decoder.html` を開き、画像 / PDF を読み込む
3. 四隅の黒い■（ファインダ）を **自動検出** → 赤いグリッド枠が表示される
4. ズレていたら、赤枠の四隅（青いハンドル）を **ドラッグして調整**（スマホはタッチ操作可）
5. 「このページを解析して追加」→ ヘッダのページ番号で自動的に整理される
6. 全ページが揃ったら「全ページ結合してファイル保存」→ 元ファイルが復元されます

## 🧩 仕組み

### カードフォーマット（`js/card-format.js` に集約）
エンコーダ・デコーダの両方がこの1ファイルを共有し、幾何形状とヘッダ仕様のズレを防ぎます。

| 項目 | 値 |
|------|----|
| 用紙 | A4 固定 |
| 解像度 | 300 dpi（`2480 × 3508 px`） |
| グリッド | `96 列 × 96 行`（1セル = 1bit） |
| 1セル | 約 `19.4px` ≈ `1.64mm`（正方形） |
| ヘッダ | 先頭1行（96bit = 12byte） |
| ペイロード | 残り `95 × 96 = 9120bit = 1140 byte / ページ` |

### ヘッダ（12 byte）
| offset | 内容 |
|--------|------|
| 0..1 | MAGIC `0x4E 0x43`（"NC" = Naidesu Card） |
| 2 | VERSION（=1） |
| 3 | pageIndex（0始まり） |
| 4 | totalPages（総ページ数） |
| 5..6 | このページの有効ペイロード長（big-endian 16bit） |
| 7..10 | ファイル全体のバイト数（big-endian 32bit） |
| 11 | チェックサム（0..10 の XOR） |

このヘッダにより、**バラバラの順序でページを読み込んでも正しく結合**でき、
ズレた読み取りは**チェックサムNGで検出**して赤枠の再調整を促します。

### 自動位置検出
四隅に **黒い正方形のファインダマーカー**を配置しています。左上(TL)だけは
「黒四角の中に白抜き＋中心に黒点」の特別マークにして**向きを一意**にしています。

デコーダは以下の流れで四隅を自動検出します（歪みなし・まっすぐ動かす前提）:

1. グレースケール化 → **大津の二値化**（縮退対策として黒/白平均の中点を採用）
2. **連結成分ラベリング**で黒い塊を抽出
3. サイズ・アスペクト比・充填率で「ファインダらしい塊」を選別
4. 画像の四隅に最も近い塊の重心を採用
5. ファインダ中心 → データグリッド四隅へ幾何補正（`finderToGrid`）

検出できない/ズレる場合は、赤枠の四隅を手で合わせれば確実に読めます。

## 🧪 テスト

Node.js（Canvas不要の純JS）で往復一致を検証します。

```bash
node test/roundtrip.test.js    # 生成→理想座標サンプリング→復元 が byte-exact
node test/autodetect.test.js   # 生成→自動検出(otsu+連結成分)→復元 が byte-exact
```

ブラウザでの実描画・実JPEG圧縮を含むE2Eは、静的サーバを立てて開きます。

```bash
python3 -m http.server 8000
# → http://localhost:8000/test/browser-e2e.html （タイトルが "E2E PASS" になれば成功）
```

検証済みケース: 小さいテキスト / 1KBランダム / 複数ページ / スキャン解像度違い(1.3x) /
余白(平行移動)付き / **JPEG圧縮(0.9)経由**。いずれも byte-exact で復元。

## 💡 印刷・スキャンのコツ

- 印刷は **等倍（100% / 実サイズ / 拡大縮小なし）** が理想。
- 白黒でOK。**四隅の黒い■を切らない**（自動位置合わせに必須）。
- スキャンは **300dpi 前後**。傾き・歪みは無い前提なので、原稿はまっすぐ置く。
- 撮影する場合は真上から、影・反射が入らないように。
- うまく読めないときは Decoder の赤枠を手動で微調整、または「白黒反転」を試す。
