# 📇 naidesu-cardloader

> (何もかも)ないです — バイナリ ⇄ 紙のパンチカード変換ツール（A4 / 300dpi）

任意のファイル（バイナリ）を、A4に印刷できる「パンチカード」画像に変換し、
それを **印刷 → スキャン** して、再びバイナリに復元するための
完全ブラウザ完結（サーバ不要）の静的Webアプリです。

- **作成 (Creator)**: `バイナリ → カード画像(PDF / PNG / JPG) → 印刷`（**1KB〜5KB** の密度モード＋**誤り訂正レベル**を選択可）
- **読み取り (Decoder)**: `印刷物を300dpiでスキャン → 自動検出 → 誤り訂正 → バイナリ復元`（**モード・誤り訂正レベルとも自動判別**）

> **✨ 誤り訂正（リードソロモン）対応**: GF(256) 上の Reed-Solomon 符号を実装し、
> 印刷物の**汚れ・かすれ・JPEG劣化で一部のマスが化けても自動で訂正**できるようになりました。
> 訂正の強さ（パリティ量）は作成時に **なし / 低(≈10%) / 中(≈20%) / 高(≈30%)** の
> **4段階から選択**できます。
> 攻めた **5KB モード（1ページ 5376 byte・1セル 0.93mm）** を新設しました。

pdf.js / jsPDF を利用し、外部サーバへデータを送りません（オフラインでも動作）。

## 🚀 使い方

`index.html` をブラウザで開くだけです（GitHub Pages 等の静的ホスティングでも動作）。

### ① 作成（バイナリ → 紙）
1. `creator.html` を開く
2. 変換したいファイルを選択（テキスト / 画像 / zip など何でも可）
3. **密度モード**を選ぶ（すべて **A4 全面**を使うレイアウト・数値は**総容量**）
   - **1KB モード**（96×143・1ページ 1692 byte・マスが大きく読み取り安定・**推奨**）
   - **2KB モード**（112×167・1ページ 2310 byte・枚数を減らせる）
   - **3KB モード**（130×194・1ページ 3120 byte・高密度）
   - **4KB モード**（149×222・1ページ 4116 byte・4KB のファイルも 1 枚に集約）
   - **5KB モード**（170×254・1ページ 5376 byte・1セル 0.93mm・**ページ全面を極限活用・最高密度**）
4. **誤り訂正レベル**を選ぶ（**段階的に調整可**）
   - **なし**（訂正しない・総容量をフルにデータへ）
   - **低（約10%）** — わずかな汚れ・かすれを訂正
   - **中（約20%）** — 既定。実用的な訂正力（推奨）
   - **高（約30%）** — 強い汚れ・折れにも耐える（そのぶん正味容量は減る）
5. 出力形式を選ぶ
   - **PDF**（複数ページを1ファイルに・推奨）
   - **PNG / JPG**（ページごとに個別ダウンロード）
6. 「カードを生成してダウンロード」
7. **A4に等倍（100% / 実サイズ）で印刷**（四隅の黒い■を切らないこと）

> **総容量と正味容量（＝実際に入るデータ量）**: 総容量はモードで決まり、
> そこから誤り訂正のパリティを差し引いた分が正味容量です。
>
> | モード | 総容量 | 正味 (なし) | 正味 (低≈10%) | 正味 (中≈20%) | 正味 (高≈30%) |
> |--------|-------:|-----------:|-------------:|-------------:|-------------:|
> | 1KB | 1692 B | 1692 B | 1510 B | 1328 B | 1146 B |
> | 2KB | 2310 B | 2310 B | 2061 B | 1827 B | 1593 B |
> | 3KB | 3120 B | 3120 B | 2782 B | 2444 B | 2124 B |
> | 4KB | 4116 B | 4116 B | 3674 B | 3248 B | 2832 B |
> | 5KB | 5376 B | 5376 B | 4809 B | 4263 B | 3717 B |
>
> いずれも正味容量を超えるファイルは自動的に複数ページに分割されます。
>
> **なぜ 5KB モードを作れたのか**: 4KB モードまでは
> 「マスを縮めすぎると 1 マスの読み違いが即データ破損」になるため、これ以上の高密度化には
> 慎重でした。今回リードソロモン誤り訂正を入れたことで、**多少マスが化けても自動訂正**できる
> ようになり、1セル **0.93mm**（170×254＝5376 byte）まで攻めた 5KB モードを安心して
> 提供できるようになりました。密度アップ分の“余白の無駄”をなくし、化けは誤り訂正に委ねる、
> という考え方です。
>
> **A4 全面を使うレイアウト**: データグリッドは A4(2480×3508px)の
> 上下余白・フッタを除いた **全高**(`1860×2778`)を使います（旧・正方形 `1860×1860` は
> 上半分強しか使っていませんでした）。この全面活用により、4KB でも 1セル `1.06mm` を保てます。

### ② 読み取り（紙 → バイナリ）
1. 印刷したカードを **300dpi程度でスキャン**、または正面から真っ直ぐ撮影
2. `decoder.html` を開き、画像 / PDF を読み込む
3. 四隅の黒い■（ファインダ）を **自動検出** → 赤いグリッド枠が表示される
4. ズレていたら、赤枠の四隅（青いハンドル）を **ドラッグして調整**（スマホはタッチ操作可）
5. 「このページを解析して追加」→ **モード・誤り訂正レベルを自動判別**し、
   ヘッダのリードソロモン符号で**汚れ・かすれによる誤りを自動訂正**（訂正バイト数を表示）
6. ヘッダのページ番号で自動整理 → 全ページが揃ったら「全ページ結合してファイル保存」→ 元ファイルが復元されます

## 🧩 仕組み

### カードフォーマット（`js/card-format.js` に集約）
エンコーダ・デコーダの両方がこの1ファイルを共有し、幾何形状とヘッダ仕様のズレを防ぎます。
**密度モード**は共通のジオメトリ（用紙・余白・四隅ファインダ位置・データ領域の大きさ）を
保ったまま、その共通の長方形を `cols × rows` に細分するセル数だけを切り替えます。
ファインダ位置が全モード共通なので、自動位置検出はモードに依らず1つのロジックで動きます。

> **データ領域は A4 全面**: 全モード共通のグリッド矩形は `1860 × 2778 px`
> （ページ全高 3508px から上下余白と下端フッタ分を除いた領域）で固定です。
> 以前の正方形グリッド（`1860 × 1860`）は A4 の上半分強しか使っていませんでした。

| 項目 | 1KB モード | 2KB モード | 3KB モード | 4KB モード | 5KB モード |
|------|-----------|-----------|-----------|-----------|-----------|
| 用紙 | A4 固定 | A4 固定 | A4 固定 | A4 固定 | A4 固定 |
| 解像度 | 300 dpi（`2480 × 3508 px`） | 同左 | 同左 | 同左 | 同左 |
| データ領域 | `1860 × 2778 px`（全モード共通） | 同左 | 同左 | 同左 | 同左 |
| グリッド | `96 × 143` | `112 × 167` | `130 × 194` | `149 × 222` | `170 × 254` |
| 1セル | 約 `19.4px` ≈ `1.64mm` | 約 `16.6px` ≈ `1.41mm` | 約 `14.3px` ≈ `1.21mm` | 約 `12.5px` ≈ `1.06mm` | 約 `10.9px` ≈ `0.93mm` |
| ヘッダ | 先頭2行（RS保護 18byte） | 先頭2行 | 先頭2行 | 先頭1行 | 先頭1行 |
| 総容量 | `1692 byte` | `2310 byte` | `3120 byte` | `4116 byte` | `5376 byte` |

> **ヘッダ行はモードによって 1〜2 行**: RS 保護ヘッダは 18 byte(144 bit) あり、
> 行幅が狭いモード（1KB～3KB）では 1 行に収まらないため `ceil(144/cols)` 行をヘッダに充てます。
>
> **300dpi でのセル物理サイズ**: 最も高密度な 5KB モードでも 1セル ≈ `10.9px`(`0.93mm`) を
> 確保しており、リードソロモン誤り訂正と組み合わせることで 300dpi スキャンでも安定して読めます。

### 誤り訂正（Reed-Solomon over GF(256)）
`js/reed-solomon.js` に GF(256)（原始多項式 `0x11d`、QR コード標準）のリードソロモン
符号化/復号化を実装しています。系統符号化 `[データ | パリティ]` で、ブロック長 `N=255`、
パリティ `nsym` バイトにつき **最大 `nsym/2` バイト/ブロックの誤りを訂正**できます
（Berlekamp-Massey で誤り位置多項式、Chien 探索で位置、Forney で値を復元）。

訂正レベルはパリティ比で段階化しています（ブロック単位で偶数に丸めて適用）:

| レベル | key | パリティ比 | 意味 |
|------|-----|---------|------|
| 0 | none | 0% | 訂正なし（総容量＝正味） |
| 1 | low | ≈10% | 軽微な汚れ・かすれ |
| 2 | med | ≈20% | 実用的（既定・推奨） |
| 3 | high | ≈30% | 強い汚れ・折れ |

本文はページごとに RS 符号化され、デコーダはヘッダから判別した訂正レベルで
自動的に復号・訂正します。訂正能力を超える損傷だけクリーンに失敗検出します。

### ヘッダ（12 byte の論理情報 + RS パリティ 6 byte = 18 byte）
ヘッダ自体もリードソロモン（`nsym=6`、最大 3 byte 訂正）で保護しており、
ヘッダ行の汚れでもページ情報（モード/ECC/ページ番号）を復元できます。論理 12 byte の内訳:

| offset | 内容 |
|--------|------|
| 0..1 | MAGIC `0x4E 0x43`（"NC" = Naidesu Card） |
| 2 | VERSION+モードID+ECC（下位3bit=VERSION(=3)、次3bit=モードID `0:1KB〜4:5KB`、上位2bit=ECCレベル `0〜3`） |
| 3 | pageIndex（0始まり） |
| 4 | totalPages（総ページ数） |
| 5..6 | このページの有効ペイロード長（big-endian 16bit） |
| 7..10 | ファイル全体のバイト数（big-endian 32bit） |
| 11 | チェックサム（0..10 の XOR） |

このヘッダにより、**バラバラの順序でページを読み込んでも正しく結合**でき、
ズレた読み取りは**チェックサムNGで検出**して赤枠の再調整を促します。

**モード・ECCレベルの自動判別**: デコーダはカードのモードも ECC レベルも事前に知りません。そこで
1KB〜5KB すべてのグリッドでヘッダ行を試し読み（RS でヘッダを復号）し、`MAGIC` + `checksum` が通り、
さらに**ヘッダ内モードIDとサンプリングに使ったグリッドが一致**したものを採用し、ヘッダ内の ECC レベルで
本文を復号・訂正します。これにより、読み取り側でモードも訂正レベルも手動選択する必要はありません（古い VERSION 2 ヘッダも後方互換で読めます）。

### 自動位置検出
四隅に **黒い正方形のファインダマーカー**を配置しています。左上(TL)だけは
「黒四角の中に白抜き＋中心に黒点」の特別マークにして**向きを一意**にしています。

デコーダは以下の流れで四隅を自動検出します（歪みなし・まっすぐ動かす前提）:

1. グレースケール化 → **大津の二値化**（縮退対策として黒/白平均の中点を採用）
2. **連結成分ラベリング**で黒い塊を抽出
3. サイズ・アスペクト比・充填率で「ファインダらしい塊」を選別
4. 画像の四隅に最も近い塊の重心を採用
5. ファインダ中心 → データグリッド四隅へ幾何補正（`finderToGrid`）

検出できない/ズレる場合は、赤枠の四隅を手で合わせれば確実に読めます。

## 🧪 テスト

Node.js（Canvas不要の純JS）で往復一致を検証します。

```bash
npm test                       # roundtrip + autodetect をまとめて実行
# 個別に実行する場合:
node test/roundtrip.test.js    # 生成→理想座標サンプリング→復元 が byte-exact
node test/autodetect.test.js   # 生成→自動検出(otsu+連結成分)→復元 が byte-exact
```

実Canvas + 実JPEG(0.9)圧縮を経た自動検出E2E（特に **5KBモードの高密度セル(0.93mm)が
JPEG圧縮後も RS 誤り訂正込みで読めること**の確認）は Node でも実行できます（`canvas` が必要）。
メモリ節約のため `--expose-gc` 付きで代表 3 ケースに絞っています。

```bash
npm install                    # devDependency の canvas を導入
npm run test:jpeg              # node test/jpeg-e2e.node.js
```

ブラウザでの実描画・実JPEG圧縮を含むE2Eは、静的サーバを立てて開きます。

```bash
python3 -m http.server 8000
# → http://localhost:8000/test/browser-e2e.html （タイトルが "E2E PASS" になれば成功）
```

検証済みケース（**1KB / 2KB / 3KB / 4KB / 5KB 各モード × ECC レベル 0〜3**）:
小さいテキスト / 正味容量ぴったり / 複数ページ / スキャン解像度違い(1.3x) / 余白(平行移動)付き /
**汚れ・かすれシミュレート（セルのランダム反転を RS が訂正）** / **JPEG圧縮(0.9)経由**（特に **5KBモード(1セル 0.93mm)が JPEG圧縮後も読めること**） /
**モード・ECCレベル自動判別**。いずれも byte-exact で復元。

リードソロモンコアの単体検証は `node test/roundtrip.test.js` 内の ECC 往復マトリクスとシミュレートで実施されます。

## 💡 印刷・スキャンのコツ

- 印刷は **等倍（100% / 実サイズ / 拡大縮小なし）** が理想。
- 白黒でOK。**四隅の黒い■を切らない**（自動位置合わせに必須）。
- スキャンは **300dpi 前後**。傾き・歪みは無い前提なので、原稿はまっすぐ置く。
- 撮影する場合は真上から、影・反射が入らないように。
- うまく読めないときは Decoder の赤枠を手動で微調整、または「白黒反転」を試す。
